# mojo-posix v0.1.0

**Released:** 2026-10-21 · **Commit:** the one tagged `v0.1.0` · **Previous:** first release

## What it does

POSIX processes, signals and unix sockets for Mojo: spawn a child with its own working directory, environment, process group and log file; reap it without blocking; receive signals as a pollable file descriptor; wait on many descriptors with `poll`; serve and connect over unix sockets. The standard library's process API cannot set cwd, env or a process group.

## Highlights

- Spawn with cwd, env, a new process group and stdout/stderr to a log file; kill the whole group, grandchildren included.
- `signal_fd` delivers SIGCHLD and SIGTERM as a readable fd, and `block_signals` makes that reliable under the Mojo runtime: without it 14 of 100 SIGCHLD wakeups were lost, with it 0 of 200.
- `poll` is faster than Python (1M `poll(0)`: 404 to 416 ms vs 472 to 482 ms); spawning ties, since both are the kernel's `clone` and `exec`.

## Known limits

- Linux only, glibc.
- Call `block_signals` first in `main()` before reading signals; it re-runs the binary once and raises under `mojo run`.
- Unix stream sockets only: no TCP, epoll, pipe or fork.

## Upgrade / run

```
git clone https://github.com/amarbaro/mojo-posix && cd mojo-posix && uv sync
mojo run -I src examples/quickstart.mojo
```
